# 履歴を流している間に届いたイベントが購読者に届かない

## 現象

ページを開き直すと、host は `session.events()` のスナップショットを 1 件ずつキューへ載せ、載せ終わってから購読者を足していた。Effect の `MaxOpsBeforeYield` の既定は 2048 オペレーションで、使い切るとファイバーはスケジューラへ戻る。長いログではこの列の途中で実行が戻り、走っているターンが承認要求やメッセージを publish できる。その時点の購読者集合に、開き直したページは居ない。イベントはスナップショットより後なので履歴にも入らない。承認カードが出ず、ターンは答えを待ち続ける。もう一度開き直したときにはログに残っているので、そのときは見える。

## 直し方

購読を先に足し、履歴をキューへ載せる間は `replaying` にする。その間の publish はバッファへ置き、履歴の直後に同じキューへ載せる。スナップショットに既にある seq は重ねない。バッファからキューへの受け渡しは yield しないので、バッファとフラグの間に publish は割り込まない。

## 確かめ方

```sh
pnpm exec vp test packages/ui/host/tests/host.test.ts
```

2026-10-26 に上記を実行した。`session.events` がスナップショットを返す瞬間に `session/event` を発火させ、購読側が履歴の `before` と、その読みの途中で届いた `during` の両方を受け取ることを見た。スケジューラが 2048 で戻ることは Effect 4.0.3 の `MaxOpsBeforeYield` の既定値として確認した。
