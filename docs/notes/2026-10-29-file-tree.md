# 右ペインのワークスペースファイルツリー（#388）

## 受け入れ条件

1. セッションの cwd を根にした木が、ディレクトリを開いたときに子を読む。
2. ディスク上の追加と削除が、その木に反映される。
3. 木から開いたファイルがプレビューの入口になり、プレビューが無い間は composer の `@` にパスを入れられる。

## 現状

右ペインは Changes / Run / Settings / Turns で、ファイルは `@` の補完で名前を探すだけだった。サーバにはワークスペース全体を walk する `files` 経路しか無く、1 フォルダだけを読む口が無かった。

## 方針

- サーバに `workspaceDirectory`（`{ sessionId, path }`）を足し、`path` をワークスペース根からの相対名として 1 段だけ `readdir` する。根は `''`。
- 境界は既存の `@` 参照と同じ gate に通す。`within` と `realOf` を `apps/web/src/server/inside.ts` に切り出し、`references.ts` と `files.ts` の両方が同じ判定を使う。綴った名前と symlink の解決先の両方が根の内側でなければ拒否する。
- 一覧の規則は検索と同じにする。`node_modules` と `.git` は出さず、根の `.gitignore` / `.ignore` を `makeIgnoredPaths` で適用し、ドットで始まる項目は出す。フォルダ→ファイル、各々名前順。1 フォルダ 1,000 件で切り、切ったことは `truncated` で返す。
- ページ側はツリーを `WebState.tree`（読んだフォルダと開いているフォルダ）に持つ。開いたフォルダだけを読み、閉じても読んだ内容は残す。
- 追加と削除の反映は「開いているフォルダを読み直す」で行う。タブを開いたとき・フォルダを開き直したとき・更新ボタンで読む。読めなくなったフォルダは木から外し、理由を出す。ファイル監視は入れていない（後述）。
- ファイルを押すと `draftWithReference` で下書きの末尾に `@path` を足す。プレビューができたら、この押下の行き先を差し替える。

## 残り

- ファイル監視（`fs.watch`）は入れていない。サーバに watcher が無く、ポーリングの stream を足すと CI でタイミングに依存する試験が増えるため、読み直しを明示の操作にした。監視が要るなら別 issue で stream を足す。
- 実ブラウザでの目視はしていない。テストと `build:web` の出力で確認した。
