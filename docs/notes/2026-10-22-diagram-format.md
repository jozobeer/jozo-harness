# 回答の図解はどの形式で出すか

Issue #300 の決定。図を出す形式を 3 つに絞り、それ以外を採らない理由も残す。

## 決めたこと

図はまずチャット本文に置く。本文で足りない大きさのときだけ artifact のページにする。

| 形式 | 使う場面 | 出し方 |
| --- | --- | --- |
| markdown の表 | 比較・一覧・対応（案 A と B の差、設定キーと既定値） | 本文の GFM パイプ表 |
| コードブロックの図 | 小さな関係・順序（3〜5 ノードの依存、処理の流れ） | ```text の fence。`pre.code` は横スクロールする |
| artifact の HTML ページ | 大きく視覚的な図・レイアウト・状態遷移・触れる図 | `artifact` tool。opt-in の plugin 行が要る |

## 採らない形式と理由

- **Mermaid**: レンダラは [markdown.ts](../../apps/web/src/ui/markdown.ts) の自作実装で、fence の中身を描く先が無い。描画器を足すと依存とバンドルが増え、崩れたときのフォールバック（図を捨てて本文に戻す）も設計する必要がある。図の需要は表と小さなコードブロックで足りるので、まず採らない。
- **本文のインライン SVG**: レンダラは escape 済み HTML を前提にしている。生 SVG を許すのは、要素と属性の allowlist を持つサニタイズ境界を新しく作るということ。図の頻度に対して境界の維持コストが見合わない。
- **本文の画像**: markdown の画像記法もリンクとして扱われ、画像は描かれない。

## 置き場所

- 常設: system prompt の identity に 2 文。図を出すかどうかを毎回思い出させるには、on-demand の skill では弱い。
- 詳細な作法（ノードの書き方、幅の目安）は、必要になった時点で skill に切り出す。いまは形式の振り分けだけを常設に置く。

## 残る制約

`artifact` は opt-in なので、plugin 行の無い run ではページを出せない。その場合は本文の表かコードブロックで収める。ページを既定で有効にするかは、この決定の範囲外とする。
